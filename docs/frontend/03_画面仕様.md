# OfficeNavi 画面仕様（MVP）

## 1. 画面共通仕様
- API呼び出し中は、対象操作ボタンを無効化する。
- API結果は画面上部に通知領域を持ち、成功/失敗を表示する。
- サーバーエラー（500）は共通文言を表示し、再試行操作を提供する。
- 入力不正（400）は可能な限り項目単位で表示する。

## 2. SCR-001 社員一覧画面

### 2.1 目的
- 社員一覧を確認し、各機能画面への起点とする。

### 2.2 表示項目
| 項目 | 型 | 説明 |
|---|---|---|
| id | number | 社員ID |
| name | string | 社員名 |
| email | string | メールアドレス |

### 2.3 操作
- 初期表示時に GET /api/users を実行する。
- 画面内の導線から社員登録、座席登録、現在位置照会へ遷移する。

### 2.4 状態
- ローディング: スピナー表示
- 空状態: 社員データなしメッセージ
- エラー: 再読込ボタンを表示

## 3. SCR-002 社員登録画面

### 3.1 目的
- 新規社員を登録する。

### 3.2 入力項目
| 項目 | 必須 | ルール | 実装上の制約 |
|---|---|---|---|
| name | 必須 | 空白不可 | 1-100文字、半角/全角空白禁止 |
| email | 必須 | メール形式 | 8-255文字、空白禁止 |
| password | 必須 | 英大/英小/数字を各1文字以上 | 8-255文字、空白禁止 |

### 3.3 API
- POST /api/users

### 3.4 ボタン制御
- 必須項目未入力または形式不正時は送信不可。
- 送信中は二重送信防止のため送信ボタン無効化。

### 3.5 結果表示
- 201: 登録成功通知を表示し、社員一覧画面へ戻る。
- 400: 項目単位のバリデーションエラーを表示。
- 409: メールアドレス重複メッセージを表示。
- 500: 汎用エラーメッセージを表示。

## 4. SCR-003 座席登録画面

### 4.1 目的
- 社員の着席/退席を実行する。

### 4.2 入力項目
| 項目 | 必須 | 説明 |
|---|---|---|
| userId | 必須 | 対象社員ID |
| seatId | 着席時のみ必須 | 座席ID |

### 4.3 初期データ取得
- GET /api/users
- GET /api/seats

### 4.4 操作とAPI
- 着席登録: POST /api/user-seats
  - body: { userId, seatId }
- 退席登録: POST /api/user-seats/leave
  - body: { userId }

### 4.5 結果表示
- 201/200: 成功通知
- 400: 入力不正メッセージ
- 404: ユーザーまたは座席不存在メッセージ
- 409: 指定座席が利用中メッセージ
- 500: 汎用エラーメッセージ

## 5. SCR-004 現在位置照会画面

### 5.1 目的
- 指定社員の現在位置を確認する。

### 5.2 入力項目
| 項目 | 必須 | 説明 |
|---|---|---|
| userId | 必須 | 照会対象社員ID |

### 5.3 API
- GET /api/users/{userId}/current-seat

### 5.4 表示項目
| 項目 | 説明 |
|---|---|
| userName | 社員名 |
| seat.name | 座席名 |
| seat.location | 座席位置 |
| since | 着席開始時刻 |

### 5.5 結果表示
- 200: 現在位置情報を表示
- 404: 現在位置なし/対象なしメッセージ
- 500: 汎用エラーメッセージ

## 6. 文言ガイド（初版）
- 成功: 操作が完了しました
- 入力不正: 入力内容を確認してください
- 競合: 指定された座席は現在利用中です
- 対象なし: 対象データが見つかりません
- 通信失敗: 通信エラーが発生しました。時間をおいて再試行してください
