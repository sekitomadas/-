# OfficeNavi フロント要件定義（MVP）

## 1. 目的

- 既存バックエンドAPIを利用し、社員の在席管理をWeb画面で行えるようにする。
- MVPでは最小機能を優先し、操作の分かりやすさとエラー時の復帰しやすさを重視する。

## 2. 対象範囲

- 対象機能
  - 社員一覧の表示
  - 座席一覧の表示
  - 社員の現在位置登録
  - 社員の退席
  - 社員の現在位置取得
  - 社員登録
- 対象外（MVP）
  - 認証・認可
  - 履歴参照
  - 高度な検索/絞り込み

## 3. 想定ユーザー

- 一般社員: 自分の座席登録/退席を行う。
- 管理者/総務: 社員一覧・現在位置の確認を行う。

## 4. ユースケース

1. 社員一覧を確認する。
2. 社員を新規登録する。
3. 社員を座席に着席登録する。
4. 社員を退席登録する。
5. 社員ID指定で現在座席を確認する。

## 5. API対応一覧

| No  | Method | Path                             | フロント利用用途     |
| --- | ------ | -------------------------------- | -------------------- |
| 1   | POST   | /api/users                       | 社員登録フォーム送信 |
| 2   | GET    | /api/users                       | 社員一覧表示         |
| 3   | GET    | /api/seats                       | 座席選択肢表示       |
| 4   | POST   | /api/user-seats                  | 着席登録             |
| 5   | GET    | /api/users/{userId}/current-seat | 現在位置照会         |
| 6   | POST   | /api/user-seats/leave            | 退席登録             |

## 6. 非機能要件（MVP）

- パフォーマンス
  - 一覧画面初期表示: 3秒以内（ローカル検証基準）
- 可用性
  - API失敗時に再試行可能なUI導線を用意する。
- ユーザビリティ
  - 処理中の状態（ローディング）を明示する。
  - 成功/失敗メッセージを表示する。
- セキュリティ
  - 入力値をフロント側でも最小限検証する（必須/形式）。
  - パスワード項目は画面上でマスク表示する。

## 7. 受け入れ条件

- 6本のAPIに対し、画面操作で正常系が実行できる。
- 400/404/409/500の主要エラーをユーザーが判別できる文言で表示できる。
- ローディング・空状態・エラー状態が画面上で識別できる。
